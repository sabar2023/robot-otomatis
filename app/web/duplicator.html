Duplicator BrandBisnis V5.0

Backup dan restore seluruh sistem langsung dari GitHub Actions. Tanpa terminal.
Kembali ke aplikasi

1. Buat Backup

Membuat arsip lengkap (kode, 13 tabel Supabase, auth user, konfigurasi, env rahasia) lalu mengunggahnya ke bucket privat Supabase Storage system-backups.
Buka Halaman Backup

2. Restore / Duplikasi

Menyalin arsip ke project Supabase tujuan. Isi URL project tujuan dan ketik RESTORE, lalu jalankan.
Buka Halaman Restore

Prasyarat Secrets

NamaDipakai untuk
SUPABASE_SERVICE_KEYExport database dan unggah arsip ke Storage (project sumber)
RESTORE_SERVICE_KEYService key project Supabase tujuan (khusus restore)
RESTORE_TEMP_PASSWORDPassword sementara untuk user auth yang dibuat saat restore
SETTINGS_ENC_KEYWajib sama dengan sistem lama agar API key user bisa didekripsi

Alur Backup

  1. Buka halaman Backup, klik Run workflow pada branch main.
  2. Tunggu selesai. Ringkasan menampilkan OBJECT_PATH dan SHA256.
  3. Arsip tersimpan приват di bucket system-backups. Tidak diunggah sebagai artifact publik.

Alur Restore

  1. Siapkan project Supabase baru, jalankan file docs/migration-*.sql.
  2. Set secret RESTORE_SERVICE_KEY dan RESTORE_TEMP_PASSWORD di repository.
  3. Buka halaman Restore, isi nama arsip, URL tujuan, ketik RESTORE, lalu jalankan.
  4. Setelah selesai: clone repo, set GitHub secrets/variables, deploy Cloudflare Worker.
Arsip backup memuat rahasia (API key, service key, token). Bucket Storage bersifat privat dan file arsip tidak pernah di-commit ke repo. Jangan mengubah SETTINGS_ENC_KEY jika API key pelanggan masih ingin didekripsi. Password user tidak dapat diekspor; restore memakai password sementara dari RESTORE_TEMP_PASSWORD.
